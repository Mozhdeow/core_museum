# راه‌اندازی OpenCode برای CORE AI

این اتصال همان پنل **Ask CORE AI** موزه، Inspect، مونتاژ و عیب‌یابی را استفاده می‌کند. اتصال زنده هنوز با کلید واقعی آزمایش نشده است. این کار هیچ درخواست پولی یا استقرار میزبانی‌شده‌ای انجام نداده است.

## ۱. دریافت کلید

به [OpenCode Console](https://opencode.ai/console) وارد شوید و یک Personal API Key یا Service Account Key با دسترسی مدل `kimi-k3` و اعتبار کافی بسازید. مدل و مسیر با [مستند رسمی Inference](https://opencode.ai/v2/docs/console/api/inference) و [جدول مدل‌ها](https://opencode.ai/v2/docs/console/models) بررسی شده‌اند (۲۸ اکتبر ۲۰۲۶).

اشتراک ChatGPT Plus اعتبار OpenCode نمی‌دهد. مدل‌های رایگان داخل برنامهٔ OpenCode لزوماً برای CORE مجاز نیستند؛ ممکن است حتی با کلید، خطای ۴۰۳ بدهند. از کلید رسمی استفاده کنید. کلید، رمز یا اطلاعات شخصی را داخل چت یا اسکرین‌شات نفرستید.

## ۲. محل دقیق کلید در این رایانه

فایل **`E:\core\supabase\functions\.env`** محل محلی اسرار است. اگر از قبل وجود داشته، دست‌نخورده باقی مانده است. فقط مقدار متغیر `OPENCODE_API_KEY` را در ویرایشگر خودتان وارد کنید. اگر فایل ندارید، نمونهٔ امن `supabase/functions/.env.example` را کپی کنید؛ فایل موجود را جایگزین نکنید.

```dotenv
OPENCODE_API_KEY=
OPENCODE_MODEL=kimi-k3
OPENCODE_API_URL=https://opencode.ai/inference/openai/v1/chat/completions
CORE_AI_ALLOWED_ORIGINS=http://127.0.0.1:5191,http://localhost:5191
```

مقدار کلید فقط بعد از `OPENCODE_API_KEY=` قرار می‌گیرد. این فایل gitignored است. کلید را در `.env` ریشه، متغیرهای `VITE_*`، کد یا فایل نمونه قرار ندهید. تنظیمات عمومی فعلی Supabase در فرانت‌اند باید به همان بک‌اندی اشاره کنند که تابع روی آن اجرا می‌شود.

## ۳. اجرای محلی

پشتهٔ محلی موجود Supabase باید روشن باشد و مجوزهای فعلی پروژه، از جمله تابع `core_current_role`، برقرار باشند. از پوشهٔ `E:\core` اجرا کنید:

```powershell
npx supabase functions serve core-ai --env-file supabase/functions/.env
```

پس از تغییر کلید، همین فرایند را متوقف و دوباره اجرا کنید. گزینهٔ `--no-verify-jwt` اضافه نکنید. این دستور را هنگام برنامه‌ریزی اجرای Edge با فرایند موجود `admin-users` هماهنگ کنید؛ نیازی به تغییر مجوزها یا تنظیمات مدیریتی آن نیست. برای سرویس هم‌زمان تابع‌ها می‌توان از `npx supabase functions serve --env-file supabase/functions/.env` استفاده کرد، ولی متغیرهای فعال‌سازی مدیریتی موجود باید جداگانه حفظ شوند؛ این راهنما آن‌ها را فعال نمی‌کند.

فرانت‌اند محلی پروژه با فرمان موجود `node scripts/local-supabase.mjs dev` روی `http://127.0.0.1:5191` به بک‌اند محلی متصل می‌شود. اجرای معمول Vite ممکن است به‌علت تنظیمات موجود شما به بک‌اند میزبانی‌شده اشاره کند؛ برای این آزمایش هر دو سمت باید محلی باشند. نیازی به تغییر کد یا ساخت دوبارهٔ فرانت‌اند برای تغییر کلید نیست.

## ۴. تشخیص اتصال موفق

با حساب مجاز CORE وارد شوید و Ask CORE AI را باز کنید. بدون کلید، **Offline Demo / حالت آفلاین** نمایش داده می‌شود. با تنظیم کلید، ابتدا «در حال اتصال» و سپس **OpenCode آماده است** دیده می‌شود؛ این فقط تشخیص تنظیمات است و اعتبار کلید را اثبات نمی‌کند. پس از ارسال یک پرسش و دریافت پاسخ واقعی، **Live AI / هوش مصنوعی زنده** همراه نام مدل ظاهر می‌شود. روی هر پاسخ نیز مبدأ آن مشخص است.

اگر تابع در دسترس نباشد، خطای واقعی و گزینهٔ «استفاده از نسخهٔ نمایشی آفلاین» نمایش داده می‌شود. شکست اتصال زنده هرگز خودکار به پاسخ نمایشی تبدیل نمی‌شود. تلاش دوباره دستی است؛ لغو درخواست تضمین نمی‌کند هزینهٔ پردازشی که قبلاً در ارائه‌دهنده شروع شده برگردد.

## ۵. تنظیم بعدی روی Supabase میزبانی‌شده

در داشبورد پروژهٔ صحیح، **Edge Functions → Secrets**، مقادیر `OPENCODE_API_KEY`، `OPENCODE_MODEL`، `OPENCODE_API_URL` و `CORE_AI_ALLOWED_ORIGINS` را ثبت کنید. مبدأ آخر باید نشانی دقیق HTTPS سایت، بدون مسیر یا `/` انتهایی، باشد؛ چند مبدأ با ویرگول جدا می‌شوند. `*` مجاز نیست. کلید را در خط فرمان ننویسید تا در تاریخچه نماند.

بعداً، فقط با اجازهٔ جداگانهٔ اپراتور، تابع آماده را به پروژهٔ درست مستقر کنید:

```powershell
npx supabase functions deploy core-ai --project-ref YOUR_PROJECT_REF
```

این فرمان در این کار اجرا نشده است. JWT verification باید فعال بماند. برای انتشار عمومی گسترده، علاوه بر ورود کاربر، محدودکنندهٔ مشترک بین نمونه‌های سرور و بودجهٔ سخت OpenCode لازم است: شمارندهٔ فعلی در حافظهٔ هر نمونه است، با راه‌اندازی دوباره پاک می‌شود و سقف جهانی هزینه نیست. حساب ناشناس Supabase اجازهٔ درخواست پولی ندارد.

## ۶. مسیر Go

در صورت داشتن اشتراک و مجوز مناسب، فقط متغیر سرور را تغییر دهید و تابع را دوباره اجرا/مستقر کنید:

```dotenv
OPENCODE_API_URL=https://opencode.ai/inference/go/openai/v1/chat/completions
```

مدل پیش‌فرض همچنان `kimi-k3` است. [راهنمای Go](https://opencode.ai/v2/docs/console/go/) این مسیر را برای Kimi K3 ثبت کرده، اما Go را برای ترافیک معمول عامل‌های کدنویسی معرفی می‌کند. پیش از استفادهٔ آموزشی/عمومی CORE، مجازبودن این کاربرد را با ارائه‌دهنده بررسی کنید؛ مسیر پرداخت بر اساس مصرف انتخاب پیش‌فرض است. برنامه هویت واقعی `CORE-Museum-Assistant/1.0` و شناسهٔ مستعار گفتگو می‌فرستد و خود را عامل دیگری جا نمی‌زند.

## ۷. رفع خطا و بررسی منطقه

| پیام | بررسی لازم |
| --- | --- |
| ورود لازم است / HTTP 401 | دوباره به CORE وارد شوید؛ توکن باید متعلق به همان پروژه باشد. JWT را غیرفعال نکنید. |
| کلید OpenCode پذیرفته نشد | اپراتور مقدار کلید سرور و لغونشدن آن را در Console بررسی کند. کلید را برای دیگران نفرستید. |
| HTTP 403 | مجوز حساب CORE، مبدأ دقیق، دسترسی مدل، مدل رایگان مخصوص برنامه، شرایط Go و سیاست منطقه/Privacy را بررسی کنید. |
| Rate limited / HTTP 429 | دست‌کم یک دقیقه صبر کنید؛ سقف ساعتی، بودجه یا سهمیهٔ ارائه‌دهنده ممکن است بیشتر زمان ببرد. |
| Provider unavailable | اعتبار/بودجه، شناسهٔ مدل، اتصال خروجی، DNS/TLS و پاسخ سرویس را در Console بررسی کنید. خطاهای خام upstream به مرورگر فرستاده نمی‌شوند. |
| Timeout | شبکهٔ میزبان به OpenCode را بررسی کنید؛ فقط در صورت نیاز دستی دوباره تلاش کنید. |

از **همان شبکه یا منطقهٔ استقرار تابع** می‌توان بدون کلید و بدون inference، دسترسی HTTP به فهرست مدل‌ها را بررسی کرد:

```powershell
curl.exe --fail --silent --show-error https://opencode.ai/inference/v1/models
```

این فقط اتصال پایه را نشان می‌دهد و مجوز حساب/مدل یا دسترسی از منطقهٔ تابع را ثابت نمی‌کند، مگر از همان محیط اجرا شود. بعد از آماده‌شدن کلید و استقرار، یک پرسش کوتاه از پنل بفرستید و پاسخ Live AI را ببینید. موفقیت از رایانهٔ شخصی به‌تنهایی موفقیت در منطقهٔ میزبان را ثابت نمی‌کند. محدودیت‌های شبکه، منطقه و حساب را از مسیر پشتیبانی رسمی بررسی کنید.

تنها شناسهٔ اثر برای موزه به سرور می‌رود؛ سرور اطلاعات منتشرشده را با مجوز کاربر می‌خواند. برای Lab فقط نصب‌ها، اتصال‌های لازم، انتخاب فعلی، وضعیت برق/پنل و شناسهٔ درس منتقل می‌شوند. حداکثر شش پیام مرتبط اخیر ارسال می‌شود. پروفایل، نام، ایمیل حساب، متن Notepad، کل کاتالوگ و فایل‌های کاربر وارد درخواست مدل نمی‌شوند. ایمیل و الگوهای شناخته‌شدهٔ توکن در متن نیز پوشانده می‌شوند؛ اطلاعات خصوصی را وارد گفتگو نکنید. تاریخچه فقط در حافظهٔ مرورگر است؛ شرایط نگهداری دادهٔ ارائه‌دهنده جداگانه در مستندات آن آمده است.
